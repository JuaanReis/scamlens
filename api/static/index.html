Arquitetura do ScamLens

O ScamLens expõe uma REST API construída com FastAPI e servida por Uvicorn atrás de um reverse proxy Nginx. A API atua como camada de orquestração entre os motores scurl (URLs) e scqr (QR codes), além de gerenciar autenticação, cache, quotas e logging.

Entrypoint e ciclo de vida

Inicialização via lifespan do FastAPI:

@asynccontextmanager
async def lifespan(app: FastAPI):
    setup_file_logging()
    init_database()
    yield
    teardown_logging()

app = FastAPI(lifespan=lifespan)

Em produção, docs são desabilitados via SCAMLENS_ENV=production.

Autenticação

JWT curto (15 min) + refresh token rotativo (7 dias). Ambos via cookies httpOnly.

Fluxo

POST /auth/login → emite JWT + refresh cookie
POST /auth/refresh → renova tokens
POST /auth/logout → invalida refresh

Pipeline de análise (URL)

request → quota → cache → scurl.run_engine → persist → response

O motor scurl é stateless.

Pipeline de QR

upload → validate → decode → classify → route → analyze → persist
  • pyzbar como decoder primário
  • zxingcpp como fallback
  • classificação por prefixo do payload

Rate limiting e quotas

  • Rate limit por IP (429)
  • Quota diária por usuário/IP
  • Semaphore para concorrência máxima

Cache

Cache baseado em SHA-256 da URL normalizada. Evita reexecução do pipeline completo.

Middleware

Logging em nível de requisição (ASGI middleware) e logging de API em nível de rota.

Banco de dados

SQLite em modo WAL com conexões thread-local.
