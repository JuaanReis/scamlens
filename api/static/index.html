ScamLens API

API REST para detecção de phishing em URLs e QR codes. Autenticação, quotas de uso e formato de resposta descritos abaixo.

Convenções gerais

  • Base URL: https://scamlens-production.up.railway.app
  • Formato: application/json, exceto upload de QR (multipart/form-data)
  • Autenticação: cookies httpOnly e JWT.
  • Case: chaves JSON em snake_case

Autenticação

Token de acesso de curta duração + refresh token para renovação, sem exigir novo login. Uso via navegador: cookies httpOnly. Uso via CLI/scripts: Bearer token.

MétodoRotaAuth necessáriaDescrição
POST/auth/registerNãoCria novo usuário
POST/auth/loginNãoAutentica e emite cookies de sessão
POST/auth/refreshCookie de refreshRenova a sessão
POST/auth/logoutCookie de sessãoEncerra a sessão

POST /auth/register

Request body

{
  "username": "string",
  "email": "string",
  "password": "string"
}

Response 201

{
  "id": 7,
  "username": "carlos",
  "email": "carlos@example.com"
}

Erros: 409 username/e-mail já em uso, 422 campo inválido.

POST /auth/login

Request body

{
  "username": "string",
  "password": "string"
}

Response 200 — tokens entregues via Set-Cookie (httpOnly):

{
  "ok": true
}

Erros: 401 credenciais inválidas.

POST /auth/refresh

Sem body — usa o cookie de refresh existente. Retorna 204 em caso de sucesso.

Erros: 401 sessão ausente ou expirada.

POST /auth/logout

Sem body. Response 204.

Rate limiting e quotas

RegraValorEscopo
Rate limit10 req/minPor IP
Quota não-autenticado3 scansPor IP, antes de exigir login
Quota autenticado⚠ não documentadoPor usuário

Ao exceder rate limit ou quota, a API retorna 429. ⚠ Confirmar se há header Retry-After — sem ele, o cliente não sabe quanto tempo esperar.
