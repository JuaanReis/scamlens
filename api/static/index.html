ScamLens API

API de análise de URLs, QR codes, arquivos executáveis e Pix copia e cola. Use a origem em que esta página está aberta como base das rotas abaixo.

Requisições usam JSON, exceto uploads multipart. A autenticação usa cookies httpOnly; rotas protegidas também aceitam Authorization: Bearer <access_token>.

Autenticação

MétodoRotaResposta
POST/api/auth/register201, usuário e cookies
POST/api/auth/login200, ok e cookies
POST/api/auth/refresh200, ok e cookies renovados
POST/api/auth/logout200, ok e cookies removidos

Cadastro

POST /api/auth/register
Content-Type: application/json

{
  "name": "Carlos",
  "email": "carlos@example.com",
  "password": "uma-senha-forte"
}

Login

POST /api/auth/login
Content-Type: application/json

{
  "email": "carlos@example.com",
  "password": "uma-senha-forte",
  "remember": false
}

Login retorna {"ok": true} e envia os tokens em cookies. Refresh usa o cookie refresh_token e só permite uma renovação por token. Logout revoga os tokens apresentados e remove os cookies.

Análise de URL

POST /api/scurl/analyze/url
Content-Type: application/json

{
  "url": "https://example.com",
  "use_cache": false
}

A resposta 200 contém scan e target. O score vai de 0 a 100 e não representa probabilidade de fraude. O resultado inclui status, engine, meta, result, stats, heuristics e insight. Falha técnica das regras ou ausência de cobertura válida devolve erro; não é classificada como segura.

Consultas: GET /api/scurl/scans?limit=20&offset=0 e GET /api/scurl/scans/{scan_id_ou_url_hash}. Esse histórico de URL/QR é público. Para o histórico do usuário autenticado, use /api/user/scans.

Análise de QR code

POST /api/scurl/qr/analyze/qr
Content-Type: multipart/form-data

file: imagem com QR code

O campo é file; formatos aceitos incluem PNG, JPEG, WebP e GIF. O QR deve conter uma URL HTTP ou HTTPS. O limite de bytes vem da configuração de uploads. QR sem URL válida retorna erro 400.

Análise de arquivo

POST /api/scfs/analyze/file
Content-Type: multipart/form-data

file: executável ou script

A análise é estática e não executa o arquivo. O limite padrão é 50.000.000 bytes. Histórico protegido: GET /api/scfs/scans e GET /api/scfs/scans/{scan_id}.

Análise de Pix

POST /api/scpix/analyze/pix
Content-Type: application/json

{
  "payload": "cole aqui o Pix copia e cola completo",
  "expected": {
    "merchant_name": "LOJA EXEMPLO",
    "amount": "35.90"
  }
}

expected é opcional e seus valores são strings. O payload tem limite de 4.096 caracteres. O motor verifica estrutura e contexto do BR Code, sem iniciar pagamentos ou resolver cobranças dinâmicas. Histórico protegido: GET /api/scpix/scans e GET /api/scpix/scans/{scan_id}.

Exemplo de mensagem: POST /api/chat/messages com JSON {"content":"Olá!","sent_at":"2026-10-24T17:30:00-03:00"}. Essas rotas exigem autenticação. O WebSocket valida a origem e a sessão, encerrando acesso após revogação ou expiração. Frontends em outra origem precisam constar na configuração CORS.

Health

GET /health é liveness e informa status, datetime e db. O campo db pode ser ok ou error; HTTP 200 indica que o processo respondeu. GET /health/version exige administrador.

Limites e cotas

O limite padrão é de 10 requisições por minuto, por IP, rota e método em cada processo. Respostas 429 de frequência incluem Retry-After.

UsuárioCota diária padrão
Anônimo3 por IP, compartilhadas entre módulos
standard5 por módulo
go_pro25 por módulo
plus_premium / administradorSem limite diário

A cota é reservada antes da análise e devolvida em erros normais. Cancelamento após início do motor mantém a cobrança. Saturação das vagas retorna 503.

Respostas e erros

Envelope de sucesso: {"scan": {...}, "target": {...}}. O objeto scan contém status, engine, meta, result, stats e heuristics. Em scan.result estão score, risk_level e verdict. Os campos adicionais variam conforme o módulo.

SCURL usa os vereditos safe, suspicious, dangerous e malicious. Arquivos e Pix podem responder partial ou inconclusive; score inconclusivo é nulo. Seus vereditos são específicos ao módulo.

StatusCondição
200 / 201Sucesso / cadastro ou mensagem criada
400Falha de análise ou entrada inválida no motor
401 / 403Sessão ausente ou inválida / acesso negado; cota anônima atingida usa 401
404Análise não encontrada
409E-mail já cadastrado
413 / 415Upload excede limite / formato não suportado
422Campos inválidos ou ausentes
429Frequência ou cota do plano excedida
503Servidor ocupado ou persistência de análise indisponível

As respostas de erro podem conter detail, error ou o envelope de erro do motor. A configuração do servidor determina os limites efetivos.
